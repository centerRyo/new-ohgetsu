# 日本向けアレルギー関連 新規アプリ事業 提案

> ohgetsu(アレルギー対応レストラン検索)とは別の新規事業として、日本向けアレルギー関連アプリの事業アイデアを検討したレポート。`allergy-market-research.md`・`allergy-business-landscape.md` の既存調査に加え、花粉症・アトピー領域の海外事例を追加調査した上でまとめた。

| 項目 | 内容 |
|---|---|
| 前提 | 個人〜小規模チームでの新規法人化、自己資金の範囲(〜数百万円)、開発者は基本的に本人のみ |
| 関心領域 | 食物アレルギー／アトピー・皮膚アレルギー・じんましん／花粉症・鼻炎・喘息 |
| 避けたい収益モデル | 広告モデル、医薬品・治療領域(資本集約的) |
| 関心のある収益モデル | B2B SaaS / API |
| 作成 | 2026-08-06 |

---

## 前提の整理

事業者の条件から、実現可能な事業の「型」はかなり絞り込める。

| 条件 | 意味すること |
|---|---|
| 個人〜小規模、自己資金数百万円 | 在庫・製造・臨床試験・医療ライセンスを伴う事業は不可 |
| 広告モデル除外 | 製薬企業の無料マーケティングツール型(Klarify等)は除外 |
| 医薬品・治療領域除外 | 免疫療法・診断キット・処方薬連携は除外 |
| B2B SaaS/APIに関心 | Edamam型が有力な参照モデル |
| 技術的強みなし、ゼロベース | データ構築・スクレイピング等、実装難易度が高すぎるものは避ける |

この制約で残る「実証済みパターン」は事実上2つ。**Yuka型(B2C・広告ゼロ・サブスク・スキャン)** と **Edamam型(B2B・API課金)**。この2つを軸に、関心領域ごとに4案を設計した。

## 追加調査 — 花粉症・アトピー領域の海外事例

既存2つのdocsは食物アレルギー中心の調査だったため、花粉症/呼吸器・アトピー/皮膚領域を追加調査した。

### 花粉症・鼻炎・喘息

- **Zyrtec AllergyCast**(米・J&J系)、**ALK-Abelló「Klarify」**(デンマーク) — いずれも無料・広告なしだが、製薬企業が自社製品(抗ヒスタミン薬・免疫療法製品)への送客・患者エンゲージメント目的で無料提供するマーケティングツール。個人開発者が再現できる収益構造ではない。
- **Propeller Health**(米) — 吸入器センサー+アプリで慢性呼吸器疾患を管理。製薬企業とのB2B提携が収益源で、2019年に**ResMedが2.25億ドルで買収**。ハードウェア前提でB2B、個人〜小規模には資本・規制面で困難。
- **Curex / HeyAllergy**(米) — Wyndly類似のオンライン処方+SLIT(舌下免疫療法)D2Cサブスク(月$47〜59)。医師免許・処方薬取り扱いが前提で、無資格の個人には不可。

→ **「広告なし・個人規模で完結する単体ソフトウェア」の成功事例は確認できなかった。**

### アトピー・皮膚アレルギー

- **Curology**(米) — 皮膚科医監修のカスタム処方スキンケアD2C、月額$19.95〜。コロナ禍で急成長し年商2億ドル超。医療行為(処方)を伴うテレヘルス。
- **First Derm**(米)・**Piction Health**(米)・**Miiskin**(欧州) — 皮膚科遠隔診療・AI肌診断。都度課金またはサブスク+B2Bライセンスの複合型。医師関与が前提。
- **EczemaWise**(米、非営利National Eczema Association運営) — アトピー管理アプリだが**2026年12月末でサービス終了予定**。
- **INCIDecoder**(ハンガリー) — 化粧品成分辞書、無料提供だが収益源は公開情報から不明。
- **Dermalytics API** — 化粧品成分安全性データをAPI提供する構想(皮膚版Edamam)だが、alpha版で実績未確立。

→ **Yuka/Edamam型で明確に黒字化した海外の個人〜小規模事例は見当たらず**、市場の空白か「儲からないから存在しない」かの判別が難しい高リスク領域。

この結果、**食物アレルギー領域(Yuka/Edamamという実証済みモデルが存在)の方が、花粉症・アトピー領域より個人〜小規模での再現性が高い**と判断する。

## 提案する4つの事業案

### 案1: 食品表示スキャンアプリ「特定原材料チェッカー」(Yuka型 × 食物アレルギー・B2C) ★推奨

- **コンセプト**: 加工食品のバーコードをスキャンし、消費者庁の特定原材料(義務8＋推奨20、2026年4月カシューナッツ義務化)の該当有無を即座に表示。保護者・食物アレルギー当事者向け。
- **収益モデル**: フリーミアム・サブスク(月300〜500円/年2,000〜3,000円)。無料は義務8品目・限定回数、有料は推奨20品目・複数プロファイル・オフライン対応。広告なし。
- **実現可能性**: バーコードスキャン自体は容易。最大の負荷は「JANコード×商品×アレルゲン表示」DBの構築。MVPでは大手コンビニPB等、数百〜1,000SKU程度に絞り込むのが現実的。ユーザー投稿型で拡張する設計が必須。
- **規制**: 表示情報の転記・検索であり医療機器等には該当しないが、誤情報によるアレルギー事故の責任論点があり、免責設計が必須。
- **追い風**: 法定表示制度により情報構造がすでに標準化されている。
- **向かい風**: コンビニ各社が自社アプリで同等機能を出す可能性、データ網羅性の初速確保の難しさ。
- **最初の一歩**: アプリを作る前に、食物アレルギー当事者・保護者50〜100人に「店頭確認の困りごと」「有料利用の意思」をヒアリングする。

### 案2: 外食メニュー×アレルゲン判定API(Edamam型 × 食物アレルギー・B2B)

- **コンセプト**: メニュー名・レシピテキストを入力すると特定原材料28品目の該当可能性を返す判定API。想定顧客は中小飲食チェーン、学校給食システムベンダー、レシピ・宅食サービス。
- **収益モデル**: 段階制API課金(月1万〜10万円程度のティア)＋管理画面SaaSのハイブリッドも検討可。
- **実現可能性**: LLM API(Claude等)を活用したレシピ→アレルゲン推定は個人でも実装しやすく、案1ほど大規模な独自実物DBが不要。技術的負荷は中〜高だが、**B2B営業が個人開発者にとって最大の壁**になる。
- **規制**: 判定結果を「保証」として使われた場合の責任分界を利用規約で明確化する必要あり。
- **最初の一歩**: コードを書く前に給食委託会社・中小飲食のアレルギー担当者5〜10人にヒアリングし、支払い意思を確認してからLLM APIラッパーの最小APIを1社と無償トライアルする。

### 案3: 化粧品成分スキャン「肌アレルギー成分チェッカー」(Yuka型 × アトピー・皮膚) — 高リスク

- **コンセプト**: 化粧品の成分表示をスキャンし、既知の刺激性/アレルギー誘発性成分をハイライト。個人のNG成分リストを登録。
- **規制リスクが最大の懸念**: 「アレルギーを防ぐ/チェックする」という表現は薬機法の効能効果標榜規制に抵触するリスクが高い。専門家監修コストも別途必要。
- 参照モデル(Dermalytics等)自体が海外でも実績未確立であり、事業として賭けの要素が大きい。

### 案4: 花粉症・症状ログ×地域予報アプリ(花粉症・呼吸器) — 高リスク

- **コンセプト**: 花粉飛散予報＋症状ログで自分の悪化パターンを可視化。将来的に匿名集計データをB2B販売(空気清浄機メーカー等)。
- 花粉症人口は国民の半数超と市場規模は最大だが、日本気象協会・ウェザーニュース等の無料強豪と競合するレッドオーシャン。海外にも参照できる黒字化モデルが存在しない。

## 比較サマリー

| 観点 | 案1 食品表示スキャン | 案2 メニューAPI | 案3 化粧品成分 | 案4 花粉症ログ |
|---|---|---|---|---|
| 収益モデル | B2Cサブスク | B2B API | B2Cサブスク | B2C→B2Bデータ |
| 技術難易度 | 中 | 中〜高 | 中 | 低 |
| 規制リスク | 中 | 中 | 高(薬機法) | 中 |
| モデルの実証度 | 高(Yuka) | 高(Edamam) | 低(未実証) | 低(未実証) |
| 営業の重さ | 軽い | 重い(B2B) | 軽い | 軽い |
| 市場規模感 | 中 | 中 | 小〜中 | 大 |

## 推奨 — 案1「食品表示スキャンアプリ」

1. **実証済みモデルへの忠実さ**: Yuka型は「広告なし・個人規模・自己資金・黒字」という条件すべてに一致する唯一の実証モデル。案3・案4は参照モデル自体が未実証で、事業として賭けの要素が大きい。
2. **規制リスクの相対的な低さ**: 案3の薬機法リスク、案4の医療的助言の線引きに比べ、「法定表示情報の検索・転記」は規制の解釈が明確。
3. **データ構築の負荷は重いが、範囲を絞れば個人でも着手可能**: 全国の全食品を最初から網羅する必要はなく、「大手コンビニのPB商品」のようにスコープを絞ったMVPから始められる。
4. **将来の拡張性**: 案1で構築した「日本の加工食品×特定原材料DB」は、そのまま案2(B2B API)への横展開の土台になる。B2C起点→データ資産化→B2B展開という段階戦略が取れる。

**着手前に必ず検証すべき最初の一歩**: アプリを作ることではなく、対象ユーザー(食物アレルギー当事者・保護者)に対して「店頭でのアレルゲン確認に今どれだけ困っているか」「有料でも使いたいと思うか」を50〜100人規模でヒアリングし、既存の代替手段(メーカーの公式サイト確認、慣れた商品のみ購入等)で十分満足されていないかを確かめること。ここで強い需要が確認できなければ、開発着手前に軌道修正が可能である。
